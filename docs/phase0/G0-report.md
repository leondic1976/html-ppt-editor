# G0 기술 검증 보고서

**결론 먼저.** 합성 샘플 기준으로 PoC A, B, C는 모두 통과했습니다. 실제 사용자 파일로 시험한 적이 없으므로, plan.md의 G0 게이트("기존 파일 수정 가능성 증명")는 **조건부 통과**입니다. 실제 AI 생성 덱에서 재확인해야 합니다.

측정 환경은 Windows 11, Chrome, Edge, Microsoft PowerPoint 16입니다. 측정치는 이 PC 한 대의 값이고 다른 장비의 성능을 보장하지 않습니다.

## PoC A: 기존 HTML 편집

`fixtures/legacy-html/`의 합성 샘플 6종으로 시험했습니다.

| 항목                                        | 결과                                 |
| ------------------------------------------- | ------------------------------------ |
| 슬라이드 인식, 글자·사진 교체, 저장, 재열기 | 통과 (E2E)                           |
| 고치지 않은 바이트 보존                     | 통과 (단위 테스트, 바이트 단위 비교) |
| 미리보기와 원본의 화면 차이                 | 0.000% (2장 기준 픽셀 비교)          |
| 스크립트가 전부 그리는 덱                   | 편집 불가. 감지하고 안내함           |
| EUC-KR, CRLF, 대문자 태그                   | 통과. 저장 시 UTF-8로 변환           |

## PoC B: PPTX 충실도

실제 PowerPoint에서 파일을 열어 객체 종류, 좌표, 글자 크기, 노트를 읽고 슬라이드 이미지를 직접 봤습니다. 복구 요청은 없었습니다. 방법은 `scripts/verify-powerpoint.ps1`에 있습니다.

| 항목                            | 결과                           |
| ------------------------------- | ------------------------------ |
| 슬라이드 크기                   | 960×540pt                      |
| 단위 변환                       | 120px → 60pt, 100px → 50pt     |
| 그래픽, 표, 차트, 노트 객체     | 네이티브로 유지                |
| 레거시 덱 26장 → 편집 우선 PPTX | 26장, 네이티브 편집 요소 208개 |

**렌더링을 직접 봐서 찾은 결함입니다.** 모두 파일은 정상으로 열리고 구조 검사도 통과했기 때문에 자동 테스트로는 잡히지 않았습니다.

1. 원형 차트의 조각이 모두 같은 색이었습니다. 조각별 색을 지정해 고쳤습니다.
2. 제목의 마지막 글자가 다음 줄로 밀려 부제목과 겹쳤습니다. 브라우저가 잰 폭으로 상자를 만들었는데 PowerPoint의 글자 폭이 조금 더 넓었기 때문입니다. 한 줄 상자는 줄바꿈을 끄도록 고쳤습니다.
3. 변환(L2) 과정에서 글머리 기호와 번호가 보고 없이 사라졌습니다. 목록을 하나의 목록 요소로 변환하고, 단순하지 않은 목록은 손실로 보고하도록 고쳤습니다.

**남은 한계**

- 여러 줄 글상자는 글자 폭 차이로 줄이 바뀌는 위치가 달라질 수 있습니다.
- 그라데이션 배경은 슬라이드마다 PNG로 들어가 파일이 커집니다. 26장 덱의 편집 우선 PPTX는 21.6MB입니다.
- Keynote, Google Slides에서는 확인하지 않았습니다.

## PoC C: 안전한 단일 HTML

| 항목                                | 결과                                                             |
| ----------------------------------- | ---------------------------------------------------------------- |
| 네트워크 차단 + `file://`로 발표    | 통과 (Chrome, Edge)                                              |
| 악성 샘플을 가져올 때 스크립트 실행 | 실행되지 않음 (E2E)                                              |
| 외부 전송                           | 요청 없음. CSS `url()` 비콘이 남던 버그를 찾아 고친 뒤 시험 추가 |
| 변조된 네이티브 파일                | 문서 검증에 실패해 열리지 않고 스크립트도 실행되지 않음 (E2E)    |

보안 검사기 규칙은 합성 샘플로만 시험했습니다. 실제 악성코드 표본이나 대규모 정상 파일로 탐지율과 오탐률을 측정하지 않았습니다.

## 성능

마지막 전체 E2E 실행의 값입니다.

| 측정                                       | Chrome | Edge   |
| ------------------------------------------ | ------ | ------ |
| 48MB 레거시 덱 열기 (26장, 시험 코드 포함) | 13.2초 | 12.4초 |
| 100장·1000요소 문서 열기                   | 189ms  | 182ms  |
| 방향키 이동 지연                           | 21ms   | 18ms   |
| 드래그 프레임 p95                          | 17ms   | 17ms   |

48MB 파일은 처음에 45초 걸렸습니다. 큰 base64 덩어리를 토큰으로 바꿔 검사·파싱한 뒤 복원하도록 바꿔 줄였습니다.

## 확인하지 못한 것

- 실제 AI 생성 덱과 실제 사용자 파일
- 외부 사용자 시험 (plan의 G2·G3 게이트에 필요한 3명)
- Keynote, Google Slides, Firefox, Safari, macOS, Linux
- 다른 PC, 다른 글꼴 환경에서의 PowerPoint 렌더링
- 사람이 조작하는 브라우저 인쇄 창
