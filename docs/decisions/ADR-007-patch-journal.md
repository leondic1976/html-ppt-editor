# ADR-007: 원본 HTML 패치 저널과 충돌

**결정.** 편집을 원본에 대한 패치(대상 키 + 작업)로 기록하고, 저장할 때 `parse5` 소스 위치로 찾은 바이트 범위만 바꿉니다.

**대상 키.** `data-deck-edit-id`를 우선하고, 없으면 구조 경로(요소 인덱스 나열)를 씁니다. 여기에 원래 범위의 해시(앵커)를 더합니다. 대상이 없거나 앵커가 다르면 **적용하지 않고 충돌로 보고**합니다. 다른 노드를 추측해 고치지 않습니다.

**왜 재직렬화하지 않나.** `outerHTML`이나 파서의 직렬화는 따옴표·대소문자·공백·주석·잘못된 태그를 바꿉니다. 실사한 NextPPT는 이 방식이고, 저장할 때 스크립트까지 잃는 경로가 있었습니다. 소스 치환은 "손대지 않은 부분은 바이트까지 같음"을 테스트할 수 있게 합니다.

**저장본의 사이드카.** `<script type="application/json" id="hps-legacy-state">`에 압축한 원본과 저널, 저장 결과의 해시를 넣어 `</head>` 앞에 둡니다.

- 다시 열면 원본과 저널에서 복원하므로 수정이 두 번 적용되지 않습니다.
- 해시가 다르면 외부에서 수정된 파일이므로, 현재 내용을 새 원본으로 삼고 알립니다.

**큰 base64.** 파서는 글자 단위로 읽으므로 내장 이미지가 시간을 대부분 차지합니다. 파싱 전에 64KB 이상의 base64 구간을 토큰으로 바꾸고 출력에서 복원합니다(`shrinkBlobs`). 48MB 파일의 파싱이 6.8초에서 0.2초로 줄었습니다.

**실행 취소.** 저널의 스냅샷을 쌓습니다. 안쪽 요소를 고친 뒤 바깥 요소 전체를 고치면 안쪽 패치는 흡수됩니다.
