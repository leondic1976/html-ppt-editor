# ADR-004: PPTX 편집 우선 / 외관 우선 계약

**결정.** 두 모드를 사용자가 고릅니다.

- **편집 우선:** 글자·도형·선·표·차트를 네이티브 객체로 만듭니다. 표현할 수 없는 효과는 요소 단위로 이미지 폴백하거나 근사하고, 슬라이드·객체 ID와 함께 보고합니다.
- **외관 우선:** 슬라이드마다 그림 한 장입니다. 노트는 유지합니다.

**PptxGenJS.** 그라데이션 채우기 API가 없어 그라데이션 도형은 이미지 폴백, 곡선도 이미지 폴백입니다. WebP·AVIF·BMP는 PNG로 변환해 넣습니다. SVG는 네이티브로 삽입하며 PowerPoint 16에서 Graphic 객체로 읽히는 것을 확인했습니다.

**레거시 덱.** 편집 우선은 L2 변환을 거치고, 외관 우선은 L3 캡처를 거칩니다.

**캡처 방식.** 서버 없이 브라우저의 `foreignObject` + canvas로 캡처합니다(html-to-image). 시스템 글꼴은 렌더링되지만 네트워크로만 받을 수 있는 글꼴은 대체됩니다.

**검증의 구분.** 구조 검사(ZIP, python-pptx)는 파일이 열린다는 뜻이 아닙니다. Windows PowerPoint 16에서 열어 객체와 렌더링을 직접 확인했습니다(`scripts/verify-powerpoint.ps1`). **Keynote와 Google Slides는 확인하지 않았습니다.**

**재사용하지 않은 것.** 실사한 NextPPT의 PPTX는 슬라이드 스크린샷 방식이고 서버가 필요합니다([실사 보고서](../phase0/oss-audit.md)).
