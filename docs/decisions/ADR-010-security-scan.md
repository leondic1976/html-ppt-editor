# ADR-010: 파일 보안 검사

**배경.** 사용자가 "악성코드, 바이러스 등인지 검사하는 기능"을 요청했습니다. plan.md에는 없던 기능입니다.

**결정.** 브라우저에서 동작하는 정적 검사기(`security-scan`)를 만들고, 파일을 열기 전에 Web Worker에서 실행합니다.

- **파일을 실행하지 않습니다.** 바이트와 parse5 AST만 읽습니다.
- **"안전" 판정이 없습니다.** 판정은 악성 가능성 높음 / 위험 / 의심 / 주의 / 알려진 위협 미탐지입니다. 타입에 `safe`가 없고 테스트로 막습니다. plan §16의 "스캔 결과로 안전을 보증하지 않는다"를 따릅니다.
- **근거를 보여 줍니다.** 규칙 ID, 행 번호, 해당 코드 조각, 검사하지 못한 부분을 표시합니다.
- **위험·악성 판정이면 기본값이 "열지 않기"입니다.** 사용자는 격리 상태로 열 수 있습니다. HTML이 아닌 실행 파일 등은 열 수 없습니다.
- **네트워크를 쓰지 않습니다.** VirusTotal은 사용자가 누를 때만 해시로 조회하며 파일을 보내지 않습니다.

**왜 백신 엔진을 넣지 않았나.** 클라이언트 전용 앱에 시그니처 DB를 넣으면 크기가 커지고 금세 낡습니다. 파일을 클라우드 검사에 보내면 "파일을 전송하지 않는다"는 약속이 깨집니다. 그래서 HTML 전달 공격에 집중한 규칙을 씁니다.

**오탐 방지.** 키 입력 감지, `localStorage`, `Blob`처럼 정상 슬라이드에도 있는 것은 단독으로 경고하지 않고, 외부 전송 등과 조합될 때만 경고합니다. 잘 알려진 CDN은 "알 수 없는 서버"에서 제외합니다.

**회피 대응.** `\x65val` 같은 이스케이프와 `'ev'+'al'` 연결을 풀어 다시 검사하고, base64·data URL·`srcdoc`·SVG 안을 재귀 검사합니다(깊이 제한 있음).

**EICAR.** 표준 시험 문자열을 잡지만 소스에서는 나누어 적습니다. 그대로 두면 사용자 백신이 저장소를 격리합니다.

**한계.** [THREAT_MODEL.md](../../THREAT_MODEL.md)에 적었습니다. 규칙은 합성 샘플로만 시험했고, 실제 악성코드 표본이나 대규모 정상 파일로 탐지율·오탐률을 측정하지 않았습니다.
