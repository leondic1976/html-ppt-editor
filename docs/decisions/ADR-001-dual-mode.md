# ADR-001: 네이티브 / 레거시 이중 모드와 신뢰 경계

**결정.** 앱이 만든 문서는 JSON 모델로 편집하고(네이티브), 그 외 HTML은 원본 위에 패치로 편집합니다(레거시). 두 모드는 내부 표현을 공유하지 않으며, 레거시 → 네이티브 변환(L2/L3)만 단방향으로 있습니다.

**이유.** 임의 HTML을 절대좌표 모델로 바꾸면 flex/grid·가상요소·미디어 쿼리가 깨집니다. 최우선 사용 사례는 "글자 몇 개만 고치기"이므로 변환 없이 원본을 보존하는 경로가 필요합니다. 반대로 새 문서에는 원본이 없으니 모델이 맞습니다.

**판별.** 확장자가 아니라 내용으로 고릅니다. `hps-format` 마커가 있어도 스키마 검증과 자산 해시를 통과해야 네이티브로 열립니다. 마커는 신뢰의 근거가 아닙니다.

**대가.** 편집 기능이 두 벌입니다. 레거시에서 요소를 옮기려면 변환해야 하고, 변환하면 원본 보존이 끝납니다. 이 차이를 UI에 L1/L2/L3로 명시합니다.
